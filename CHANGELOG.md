# Changelog

## 0.7.3 (the course workspace's data folder)

- **The Companion makes the data folder an older course workspace lacks** (owner q-20261109-0117). The MC 451 and MC 501 guides, the Twitch worksheets, `write_coding_form()`, and the reliability grid all keep files in `data/` at the top of the workspace, and their R code names it in each path, such as `read_csv("data/coding-form.csv")`. The v2v-workspace template had no `data` folder until 2026-11-09, and a copy never receives later template changes, so a student who saved coding sheets at the top level got `does not exist in current working directory`. When VS Code opens a v2v-workspace copy (it holds `00-check-your-setup.qmd` and `03_Project/`, and is not the MC 427 folder) with no folder named `data` in any capitalization, the Companion makes one empty `data` folder and says so once. It never moves, renames, or writes a file; a file named `data` stops it; a second run changes nothing. Tested on a clone of the template and on a copy shaped like a student's, with loose `.csv`, `.numbers`, and `.xlsx` files at the top: every file kept its bytes and place, and `git status` did not change.

## 0.7.2 (reliability on your own data)

- **Reliability: compare two coding passes works on your own data** (owner, 2026-11-06). Its first question is now where your two passes are: **A CSV file with both passes**, **A table in my script**, a data viewer coding sheet, or **The reliability grid** for typing codes by hand. A CSV file is read with every column as text, so a 19-digit post id keeps every digit and the two passes still line up. The columns come next: every `_p1` and `_p2` pair in the table, ticked, plus **Choose the two columns myself** for any two columns with other names. Each variable gets the same block as before: keep the items coded in both passes, percent agreement, every pair of codes, Cohen's kappa, Krippendorff's alpha, and `reliability()` as a check. Before, the menu offered only a data viewer coding sheet or the grid, so a sheet coded in Excel or Google Sheets could not be checked.
- **The side panel's Data > Reliability: compare two coding passes** now opens that same first question. It opened the reliability grid directly.

## 0.7.1 (Mac readiness)

- **R: Bracketed Paste is turned off wherever it is on.** With it on, the R extension wraps every line Cmd+Enter (Ctrl+Enter) sends in paste markers that only the radian console reads. Plain R prints them: on Windows as `[200~` and `[201~`, and on a Mac, whose R reads keys with readline 5.2, as `00~` and `01~`, with an error for the line. The course workspace template set it on from 2026-07-31 to 2026-09-08, so a course folder copied in that window still has it on its Workspace tab, while Settings opens on the User tab, where it looks unticked. The Companion now turns it off in the folder's settings (and in User settings if it is on there), says so once, and leaves it alone when the R console is radian. Reproduced and toggled on a Mac (VS Code 1.126.0, R extension 3.2.2, R 4.6.2 arm64): on, R printed `00~x <- 1 + 1; print(x)01~`; off, it printed `[1] 2`.
- **Explain an R error knows the Mac spelling.** `00~` and `01~` now bring up the stray-characters explanation and its Fix it button, as `[200~` and `[201~` already did.
- **Write R code leaves out a library() line the script already has.** A block inserted below a `library(tidyverse)` or `library(v2v)` line no longer repeats it, and the "# Load the ..." comment that only introduced it goes too. Only lines above the cursor count, since a load further down would come too late. Run it still runs the whole block, so the package is always loaded. The same holds when a block goes to the end of steps.R and for the code that rebuilds coded data.
- **Right-click a line in an R script, then Run the selected lines in R.** It runs the selected lines, or the line the cursor is on, exactly as Ctrl+Enter (Cmd+Enter on a Mac) does, so every guide step that runs code can name a menu instead of a key.
- **Check my setup on a Mac** adds three rows. **XQuartz**: a warning, with the link to xquartz.org, when it is missing, because `View(data)` in a plain R terminal then stops with "X11 library is missing" (nothing else in the courses needs it). **Git**: `/usr/bin/git` is on every Mac, but without Apple's Command Line Tools it only opens an install prompt, so the row now says to run `xcode-select --install` instead of reporting Git as found. **R for Apple silicon**: a warning when an Intel R runs on an Apple silicon Mac through Rosetta, naming the arm64 installer (macOS 14 or newer) or the big-sur-arm64 folder (macOS 11 to 13). A leftover **R: Bracketed Paste** setting shows as a VS Code row too.

## 0.6.2 (run keys in Quarto documents)

- **Run keys in a Quarto document always reach R.** In a `.qmd` file, in the source editor and in Quarto's visual editor, Ctrl+Enter (run the line), Ctrl+Shift+Enter (run the cell), Shift+Enter (run the cell and move on), Ctrl+Alt+R (run all cells), Alt+Enter, and Quarto's other run keys now go through the same step as in an R script: an R terminal becomes the active one (R (AURA) when none is open) before Quarto runs the code. On a Mac the same holds for the Cmd keys. Before, the first run asked "Choose where to run", and its highlighted choice, New R Interactive window, needed a separate console program students do not have; with a shell terminal active, the code could go into the shell.
- **R starts when a Quarto document opens.** The ▷ Run Cell button on a code cell calls Quarto directly, so no key can step in front of it. The Companion now starts the R (AURA) terminal when a `.qmd` file opens and no R terminal is open, so the button finds R. It does this only in a trusted folder, never in Positron (which uses its own console), and never asks or shows an error on open. The new setting `auraR.startRForQuarto` turns it off. One case is not covered: if you have selected a PowerShell (or other shell) terminal in the Terminal panel yourself, the Run Cell button still sends the cell there, as before. The run keys switch to R first, so press Ctrl+Shift+Enter instead, or select R (AURA) in the terminal list.
- **No output under the cell.** Results still print in the Terminal and plots still open in an R Plot tab, as before; Quarto's visual editor has no way for another extension to draw output inside it.
