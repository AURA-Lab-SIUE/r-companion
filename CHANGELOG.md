# Changelog

## 0.6.0 (code parity: everything you do in the Companion leaves R that redoes it)

- **Histogram comparing two groups** draws each bar as the share of its group's messages, as its
  label says: `y = after_stat(density * width)`. It drew `after_stat(density)`, which is share per
  character, so with 5-character bands a bar read 0.04 where the share was 0.20.
- **Ctrl+Enter runs in the same R as Run it.** The R Companion now turns on the R extension's `r.alwaysUseActiveTerminal` by default. Before, the first Ctrl+Enter after Run it asked "Choose where to run the selected code", and its first choice started a new, empty R session without your tables. You can still change the setting back.
- **One install path.** The R extension no longer asks on its own to install languageserver (`r.lsp.promptToInstall` is off by default). Check my setup and Install what is missing install it with everything else.
- **One name.** The Activity Bar icon and the panel are both called AURA Lab R Companion, as on the Marketplace. The Write R code menu groups keep their names (R2 Data, R3 Describe, R4 Test).
- **Install what is missing** prints "Possible cause" only when something is still missing. A clean install used to end with two causes that did not apply.
- **Check my setup** lists each group once, and asks for v2v 0.3.6 or newer in MC 451 and MC 501 (earlier versions cannot publish your portfolio).
- **Explain an R error** recognizes the v2v package's own errors (`run_t_test()` with three groups, `clean_dates()` on text, `join_chat_streams()` missing a column, `new_portfolio()` on a folder that already exists) and "lib is not writable". It no longer mistakes the yaml package's name for a YAML error, starts empty unless what you copied looks like R output, and says when it is explaining the text you selected.
- **Importing a file outside your course folder** says in plain words why to copy it in, without naming a `data` folder MC 427 does not have.
- **Screen readers** hear that a Help link opens your web browser.

- **Every action leaves R in your steps.** The goal of this release: whatever you do with the Companion, Run my steps from the top gets the same result again, with the same file, seed, rows, and codes. That includes the things you do by hand in the data viewer.
- **Draw a coding sample (with a seed).** A new Data task picks the table (or a data file), the column to sample within (the same number from each channel, for example) or no groups, how many rows, and a seed, then saves the sample as a CSV file for coding. MC 451 and MC 501 sampling the course chat by channel get `v2v::sample_messages()`, as the course guide shows; any other table gets `set.seed()` and `slice_sample()`. MC 427 gets plain tidyverse.
- **Your coding sheet's R goes into your steps by itself.** The first code you enter in the data viewer adds the block that rebuilds your coding sheet to the end of your steps script, and the block saves the sheet as `data/derived/coding-sheet.csv`. It reads your codes file, so it stays right as you code more. Its comments say what the coding sheet is (your recorded codes, one row per item) and what the codebook is (your rules), so the two are not confused. Insert rebuild code now offers to show the block when your script already has it.
- **Codes stay on their item.** Codes are now kept by the item's own id (`row_id`, `id`, or another id column) instead of its row number, so sorting or re-saving the data file no longer moves a code to another message. Codes files from 0.5.4 keep working as before.
- **The coding sheet template's empty columns can be coded.** A column that is empty in every row, as in the course's coding sheet template, opens as a coding column.
- **Code a variable twice, for reliability.** When you add a coding column you can choose Code it twice, which makes two columns, such as `tone_p1` and `tone_p2`. Hide pass 1 takes the first pass off the screen while you code the second.
- **Reliability from your coding sheet.** The Reliability task now finds the pass 1 and pass 2 columns in your coding sheet and writes Cohen's kappa and Krippendorff's alpha for the items you coded in both passes. The reliability grid is still there: it now asks for the variable, its values from your codebook, and the number of items, and saves each variable to its own file, `data/derived/reliability-<variable>.csv`.
- **Write this view as R.** A new data viewer button writes the filters and sorts you set as `filter()` and `arrange()` code at the end of your steps, so R keeps the rows the viewer showed, in the same order, and prints how many. Number columns now filter as numbers (more than, less than, between), and blank cells sort last both ways, as in R.
- **Crosstab of your own two columns.** The Crosstab task now lets you choose the table and the two columns, such as your codes and the AI's codes on your coding sheet in MC 427 Module 4. The course example is still there. MC 427 gets plain tidyverse.
- **Agreement between two code columns** (MC 427). A new Describe task picks your coding sheet, your code column, the AI's code column, and the id column, then writes Module 4's three checks: the share of rows where the two codes match, a count of every pair, and the list of rows where they differ. Plain tidyverse.
- **The tests on your own variables** (MC 451 and MC 501). The Settings block task can now choose a column of your saved analysis file for each name the tests use (outcome, group2, group3, predictor, cat_a, cat_b), listing the columns that fit each one first. Every test reads these names, so this one choice runs them all on your variables. The course variables are still the first choice. The Settings block can also read another saved RDS file, such as your own data, and checks its columns before it writes anything.
- **Charts and summaries of your own columns.** The bar chart, histogram, boxplot, line chart, and summary by group tasks now let you choose the table and the columns, listing the columns that fit each one first (numbers for a histogram, a date or time for a line chart). The title and axis labels come out as YOUR TURN lines for you to write. The course example is still there.
- **The MC 427 tests on your own columns.** The t-test, chi-square, ANOVA, regression, and correlation tasks in MC 427 now let you choose the table and the two columns, and drop rows with a blank in either one before the test. Plain tidyverse. The course example is still there.
- **Column names with spaces work.** Every task that writes a column name puts backticks around a name such as `` `Follower Count` ``, so R reads it as one name.
- **Your own file, not only the course data.** Each task that takes columns is now tested on the course data and on a second file whose column names and types differ, and the steps it writes are run again from the top to check that they give the same result.
- **Fixed:** code the data viewer wrote went into `steps.R` instead of the script you were working in, when the script was open beside the viewer or behind the data file's tab.

## 0.5.4 (R connects to VS Code, and a help report to email)

- **The R extension comes with it.** Installing the R Companion now installs the R extension for VS Code (by REditorSupport) too, and VS Code offers to turn it back on when it is turned off. If it is still missing or off, one notice at startup has a button that shows it in the Extensions view.
- **Check my setup checks sess.** Version 3 of the R extension connects R to VS Code through a small helper package called sess, which it offers to install under the bell the first time R opens. If that question was missed, answered Not now or Don't ask again, or the install failed, R still runs your code but the status bar says `R: (not attached)`, and after Don't ask again the question never comes back. Check my setup now has a sess line for the R your terminal uses, and Install what is missing installs sess and the packages it needs (processx, later, jsonlite, and rstudioapi) into your R library, which R checks first.
- **One clear instruction for the sess question.** Every place the R Companion talks about it, including the Check your setup step of the Get Started walkthrough before you open R, now says: "The first time R opens, VS Code asks to install a helper called sess. Click Install bundled sess. You must say yes, or R will not connect. Missed it? Click the bell in the bottom-right corner to find it. If it is not there, run AURA: Install what is missing."
- **A notice when R does not connect.** If a new R terminal has not connected to VS Code 30 seconds after it opened, one notice says so, repeats that instruction, and offers Show notifications (where the sess question waits) and Install what is missing, which installs sess and its packages and opens a new R terminal.
- **Fix not attached, rewritten for the R extension 3.x.** The explanation now covers the bell, installing the helper packages from plain R with VS Code closed, and `sess::connect()` to connect an R terminal that is already open. Its button, Install what R needs to connect, closes your R terminals, installs sess and its packages, and opens a new R terminal. `.vsc.attach()` is mentioned only for R extension versions before 3.0.
- **AURA: Make a help report.** Builds one document with your Check my setup result; the versions of your computer, VS Code, R, the R extension, and the R packages that matter for connecting; whether R is connected; and the recent messages from the R Companion and the errors and warnings from the R extension. Your home folder shows as `~` and your user name is hidden. Read it over, select Copy to clipboard, and paste it into an email to your instructor. It is also in the AURA panel's Help section and in Check my setup's results. Errors printed in the R terminal still need copying or a screenshot, because VS Code does not let extensions read a terminal.

## 0.5.3 (the AURA panel, Excel import, joins, your steps, one-click fixes, clearer charts)

- **The AURA panel.** A new icon in the Activity Bar opens a panel with every R Companion task for your course: My setup (with the result of your last Check my setup in one line), Data, Describe, Test, Your steps, and Help (including the course's step-by-step guides and videos). Selecting a task writes its code, exactly as the Write R code menu does. The panel works from the keyboard and with a screen reader: open it with **AURA: Focus on R Companion View**, then use the arrow keys and Enter.
- **Import a data file (CSV or Excel).** The Data menu item that read a fixed CSV now opens a file picker for a CSV or Excel file, asks what to call the table, asks which sheet when a workbook has more than one, and shows you the columns R will read before anything is written. Press Esc at any step to write nothing. Excel files are read with `readxl::read_excel()`, which comes with the tidyverse. In MC 451 and MC 501, column names with spaces or capitals get `janitor::clean_names()`. The data viewer opens Excel sheets too.
- **Join two tables by a shared column.** A new Data menu item picks the table you keep every row of, the table you take columns from, and the column they share, then writes a `left_join()` (or an `inner_join()`) with two checks: the row count, and how many rows found no match. If the shared column repeats in the second table, you are warned before anything is written.
- **Your steps.** Write R code still puts each block into the script you have open. With no script open, it now goes to the end of `steps.R` in your course folder instead of a new unsaved file, so every block lives in one script. **Open my steps** and **Run my steps from the top** open and run that script (a Quarto file's R chunks run in order). The panel lists the `# ---- section ----` headings of your script, and selecting one jumps to it.
- **One-click fixes.** Explain an R error now recognizes `R: (not attached)`, `Connection to server got closed`, and `read ECONNRESET`, and four explanations offer a button that does the fix for you: turn off bracketed paste for this folder (the stray `[200~` characters), close R terminals and install again (`file is in use` on Windows), and update the R extension. **Check my setup** shows the R extension's version and asks for an update below 3.0.0, which cannot connect to R 4.6. **Where to get help** has keyboard and screen reader tips.
- **What is loaded in R.** The panel's **Objects in R** opens the R extension's Workspace panel, which lists every table and function in your R session.
- **Clearer charts.** The histogram comparing two groups shows each group as shares, so the small non-gaming group no longer disappears under the big gaming group. Count axes on the Twitch charts read 20,000,000 instead of 2.0e+07. Every block that loads data sets `options(scipen = 10)`, so long numbers such as the millisecond `date` column print in full while p-values stay as the course pages show them.
- **Removed:** the Check for updates command (both extension galleries update the extension for you), the settings `auraR.updates.releaseUrl`, `auraR.testChoice`, `auraR.mc427TestMenu`, and `auraR.plainCalls`, the "plain, no v2v" date item (the `clean_dates()` block already shows the plain call), and the data viewer's Export HTML button. The code the menus write for your course is unchanged by these removals.
- **Fixed:** choosing columns from a data file never worked: the column reader stopped with an R error and the menus quietly used the course defaults instead. It reads your file now, which the import preview and the join use too.

## 0.4.1 (spreadsheet keys in the coding sheet, Run it with no R open, lm.beta for MC 501)

- **The coding sheet's keys work like a spreadsheet.** In a column with a list of codes, typing on a cell picks the first code that starts with the typed letters (capitals or not), with the matching codes listed under the cell; Backspace takes letters back off, and with none left the choice is a blank, which clears the cell. Enter saves and moves down a row, Tab saves and moves right (Shift+Tab left), and Escape cancels. ## 0.3.0 (R3: the data viewer and coding sheet)

- **AURA: Open the data viewer** opens a CSV file, or an R data frame through an Rscript JSON bridge, in an AG Grid Community webview. Data values are read only, with scroll, sort, filter, and column types. Measured on m4: the 35,267-row Twitch sample parses in about 65 ms and renders in about 64 ms.
- **Coding sheet.** Add coding columns (a dropdown of allowed values typed or pasted from a codebook, or free text) and enter a value per row from the keyboard: type, Enter moves down. Autosave and undo. Codes are stored in a separate long file, `data/derived/<name>-codes.csv` (row_id, column, value, coded_at); the original file is never written. A `row_id` column is added only when the data has none.
- **Insert rebuild code.** Inserts a commented plain-tidyverse chunk that rebuilds the coded data from the original plus the codes file (read_csv, pivot_wider, left_join by row_id), in house style. Proven in R to reproduce the coded grid exactly.
- **Refresh** re-reads the data. **Export HTML for accessibility check** writes a self-contained grid for axe.
- Accessibility: the ARIA grid pattern, keyboard-only entry, a visible focus ring, `--vscode-*` theme colors, and a high-contrast rule.
- Safety: the codes file is written atomically on a debounce and flushed on close; a hard kill mid-entry loses no saved work. The original file is hashed on open and left untouched.

## 0.1.1 (R1.0.1, fixes from the leith-hp test of 2026-10-19)

- **Install what is missing** installs CRAN binaries only on Windows and macOS. R's default installed a package from source whenever the source was newer than the binary (datawizard, performance), which fails without Rtools for any package that needs compiling.
